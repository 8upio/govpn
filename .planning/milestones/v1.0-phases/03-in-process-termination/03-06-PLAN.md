## Timing: the survival window becomes probe-driven

`postHandshakeSurvival` is currently a fixed 20 seconds (`server/main.go:55`), sized in
Phase 2 for a 10-packet ping. Three new probe classes will not fit reliably, and Phase 2's
own summary records the failure mode precisely: when the server exits first, Docker
Compose's `--abort-on-container-exit` tears the whole run down mid-probe and the acceptance
criterion becomes structurally unreachable rather than merely failing.

Rather than guessing a larger constant, Task 2 makes the window **probe-driven**: the server
prints PASS as soon as it has observed at least one ICMP echo, one UDP datagram, and one
HTTP request (plus a short settle delay), or when a raised deadline elapses — whichever
comes first. Clean scenarios then finish faster than today, and the lossy scenario still has
a generous ceiling.
