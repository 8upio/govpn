Build the thing the whole phase is for: a web server a developer can point a browser at,
from inside a VPN client, that is reachable *only* through the tunnel — served by stdlib
`http.Serve` on the userspace netstack, in one command, with no TUN device and no

## Planner assumption: the status page's field set (UI-SPEC unresolved row)

`03-UI-SPEC.md`'s UI Considerations table carries one ⚠ unresolved row: *"zero-one-many |
status page | planner must confirm the exact field set against the Session/netstack public
API surface available at implementation time."* Surfaced and resolved here as an explicit
planner assumption rather than silently dropped:

**Assumption.** The `site` package deliberately does not import `github.com/8upio/govpn`
(see this plan's prohibitions and the `key_links` entry), so it cannot call
`Session.AssignedIP()` directly. Every per-request fact instead comes through stdlib
plumbing that the netstack already populates correctly, proven by plan 03-03's
`*net.TCPAddr` handling:

| UI-SPEC locked field | Source | Fallback |
|---|---|---|
| Assigned tunnel IP | the IP half of `*http.Request.RemoteAddr` — for a netstack conn this *is* the client's assigned tunnel IP | em dash |
| Server tunnel IP | the IP half of the `net.Addr` under `http.LocalAddrContextKey` in the request context | em dash |
| Cipher | `site.Options.Cipher`, supplied by the embedder (`"AES-256-GCM"`, fixed per project scope) | em dash |
| Session status indicator | the literal text "tunnel: active" in `--color-accent` | not applicable |

Discretionary additional fields, included because they are cheaply available and make the
page more convincing as live proof: the client's source port (from `RemoteAddr`), the
request time, and the server's uptime (from `site.Options`). Every row obeys the same em-dash
fallback rule — a field that cannot be computed renders an em dash and the row stays.

**Risk if the assumption is wrong:** if a future embedder serves this site over a listener
whose conns are *not* netstack conns, `RemoteAddr` would be an ordinary socket address
rather than a tunnel IP, and the page would honestly display that address — it would be
mislabeled, not broken. Acceptable for an example whose entire purpose is being served over
the netstack.

**`examples/tunnelweb/site/site.go`.** Package `site`, importing only stdlib. It exports:

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Tunnel client's browser → `http.Handler` | The peer is authenticated at the VPN layer, but everything it *submits* — form values, header values, paths — is untrusted input |
| Submitted form value → rendered HTML | The echo page's entire purpose is reflecting peer-supplied text back into a document the peer's browser parses |
| Request headers → rendered HTML | The headers page reflects every header the peer chose to send, verbatim |
| `main.go` → `ovpn` + `netstack` | The example is the reference wiring a real embedder will copy; a bad pattern here propagates |
