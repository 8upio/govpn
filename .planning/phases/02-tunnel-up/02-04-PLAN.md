<objective>
Close the phase: prove the tunnel survives a realistic bad link, freeze real-client
data-channel bytes into the fast tier so the two conventions that fail silently can
never regress unnoticed, and turn the phase's prohibitions into a test that runs on
every commit.

**Phase goal (ROADMAP, verbatim):** "The client brings its tunnel interface up with a
pushed IP and cipher, and encrypted IP packets round-trip between the client and the
embedder's `Session`." Plans 02-02 and 02-03 delivered it on a clean link; this plan
proves it on a lossy one and makes it non-regressable.

Purpose: RESEARCH.md's two headline findings - the inverted key direction and the
tag-before-ciphertext wire order - both pass any test built only from this project's own
encrypt and decrypt. The only assertions that catch them are seeded from bytes a real
OpenVPN client actually produced. Phase 1 established exactly this pattern for tls-crypt;
this plan extends it to the data channel.

Output: extended `lossy-large` assertions, a data-channel decode path in the harness,
committed real-client vectors with provenance, and a standing prohibition gate.
