<objective>
Make sessions end. A client that sends explicit-exit-notify is torn down at once rather than after
a timeout, a session that goes silent is reaped, and every teardown — from any cause — leaves no
goroutine, no pool entry, and no routing-table entry behind.

Phase goal (ROADMAP, verbatim): *A connected client stays usable for hours and leaves cleanly —
key renegotiation does not break traffic, and dead sessions do not accumulate.*

Purpose: SESS-05. This is the second half of the phase's user-visible behavior and the precondition
for the soak run in plan `04-04` measuring anything meaningful.
Output: OCC_EXIT detection on the authenticated data channel, an idle-session reaper on an
injectable clock, and `io.EOF` from both `Read` and `Write` after teardown.
</objective>

<user_decisions>
Decisions this plan implements (from `04-CONTEXT.md`; IDs continue the project's D-NN series):

- **D-21** — Recognize the client's explicit-exit-notify (the classic data-channel OCC_EXIT
  message, verified in RESEARCH Pattern 5 against `occ.c:55-58`, `occ.h:29-30,67`,
  `forward.c:1196-1207`, `sig.c:352-392`) and tear the session down immediately.
- **D-22** — Silent sessions are reaped after no authenticated traffic for the pushed ping-restart
  window (60s), with an injectable clock for tests. `Session.Read`/`Write` return `io.EOF` after
  teardown from any cause; `Close()`'s idempotency contract holds; no new callback. Reaping flows
  through the existing `Session.Close()` → netstack read-loop-error → `Detach` path, adding no new
  coupling.

Deferred and deliberately absent: `OnSessionClosed`, server-sent exit-notify on shutdown, and
configurable reap timeouts beyond the pushed keepalive.
</user_decisions>

      not panic.

    - After the rollover in plan `04-01`, an OCC_EXIT sealed under the LAME-DUCK key inside the

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet → `Server.Serve` UDP read loop | Arbitrary datagrams from any host; nothing trusted before authentication. |
| AEAD-authenticated data plaintext → session lifecycle decisions | Only a payload that opened under a live data key can influence teardown; that is the same boundary already protecting all tunnel traffic. |
| Server clock → session lifetime | The reap decision is server-authoritative and does not depend on any peer-supplied timestamp. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-06 | Denial of Service | exit-notify spoofing (forged OCC_EXIT to force premature teardown) | high | mitigate | Task 1: the magic is checked ONLY after `datachan.Wrapper.Open` succeeds, so an attacker needs both the tls-crypt key and a live data key to produce a payload that is even examined; a `TestPhase4ExitNotifyCheckedOnlyPostDecrypt` gate keeps the ordering from regressing. |
| T-04-07 | Denial of Service | idle-reap timer kept alive by forged traffic | medium | mitigate | Task 2: the idle timer is touched only on a delivered control packet or a successful decrypt; a failed decrypt never touches it, with a dedicated negative test. |
| T-04-08 | Denial of Service | reap of a legitimately busy-but-quiet session (false-positive teardown) | medium | mitigate | Task 2: the window is 60s against a 10s pushed ping schedule, so a live client resets it six times over per window; control-channel traffic resets it too, so a mid-renegotiation session is never reaped. |
| T-04-09 | Denial of Service | resource exhaustion from sessions that never end (goroutine/pool leak) | high | mitigate | Task 3: `TestNoGoroutineLeakAcrossSessionLifecycle` plus the `TestPhase4TeardownAlwaysFlowsThroughClose` gate; plan `04-04` measures the same property against the real client over 20 cycles. |
| T-04-10 | Repudiation | no record of why a session ended | low | accept | CONTEXT defers `OnSessionClosed`; the embedder observes teardown as `io.EOF` from `Read`/`Write`. Revisit only when an embedder needs the distinction. |
| T-04-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package-manager installs in this plan; enforced by `TestPhase4NoNewModuleDependencies` (added in `04-01`) and the `git diff --stat go.mod go.sum` check in each task's acceptance criteria. |
