<objective>
Prove the whole govpn library path end-to-end on the thinnest possible slice: a single
tls-crypt-wrapped `P_CONTROL_HARD_RESET_CLIENT_V2` arrives over UDP, is authenticated,
decrypted, parsed, and answered with a `P_CONTROL_HARD_RESET_SERVER_V2` the peer can
authenticate and decrypt back.

**User story (MVP):** **As a** Go developer embedding govpn, **I want to** stand up an
OpenVPN server with `ovpn.NewServer(cfg).Serve(pc)` that a real OpenVPN 2.6 client's very
first packet reaches and gets a valid protocol answer from, **so that** the wire format,
the tls-crypt construction, and the key-direction convention are proven correct before any
TLS, reliability, or session machinery is built on top of them.

Purpose: every byte-layout mistake in this protocol is silent by design. Proving the
opcode/session-ID/ACK-array layout and the tls-crypt MAC-then-CTR construction on a
one-packet round trip costs one commit; discovering the same mistake after the reliability
layer, the framing `net.Conn`, and `crypto/tls` are stacked on top costs the phase.

Output: a buildable `github.com/8upio/govpn` module with `internal/wire`,
`internal/tlscrypt`, a public `ovpn.Config`/`ovpn.Server` surface, and isolated
golden-vector tests for WIRE-01 and WIRE-04.
</objective>

Build `internal/wire` as a single file. Declare `Opcode` with the nine reachable values
taken verbatim from ssl_pkt.h: soft reset 3, control 4, ack 5, data v1 6, hard reset client
v2 7, hard reset server v2 8, data v2 9, hard reset client v3 10, wkc v1 11. Opcodes 1 and 2
are unreachable for a key-method-2 client and must be rejected rather than special-cased;
the legal range is P_FIRST_OPCODE 3 through P_LAST_OPCODE 11. Pack the leading header byte
as opcode shifted left by P_OPCODE_SHIFT (3) OR key ID masked with P_KEY_ID_MASK (0x07), and
unpack it the same way. `SessionID` is [8]byte (SID_SIZE). `PacketID` is uint32, big-endian
on the wire — this is the reliability-layer packet ID, a different type from the tls-crypt
packet ID handled in the tlscrypt package, and the two must never be assigned to each other
(RESEARCH Pitfall 1).

Implement the control-packet plaintext layout exactly as read from reliable_ack_write with
prepend true, followed by the reliability packet ID and payload: one ack-count byte, then
ack-count 4-byte big-endian packet IDs, then the 8-byte remote session ID present only when
ack-count is greater than zero, then this packet's own 4-byte big-endian reliability packet
ID, then the remaining bytes as payload. The own-packet-ID field is omitted entirely for
opcode 5 (ack-only packets carry the ACK array and remote session ID and nothing else) —
confirm this against ssl.c's ack send site and the `op != P_ACK_V1` guard before relying on
it. Cap ack-count at RELIABLE_ACK_SIZE (8) and reject anything higher. Before every field
read, check the remaining buffer length explicitly and return a typed sentinel error;
indexing a slice out of range on untrusted UDP input is the failure mode this must prevent
(RESEARCH Pitfall 3). Serialization must be the exact inverse: emitting a parsed packet
reproduces the input bytes, ACK IDs in parse order.

Build `internal/tlscrypt` in two files. The keyfile file parses the OpenVPN Static key V1
envelope (the BEGIN/END header and footer strings and a hex body decoding to exactly 256
raw bytes) into the reference's key2 layout: bytes 0-63 keys[0].cipher, 64-127 keys[0].hmac,
128-191 keys[1].cipher, 192-255 keys[1].hmac, with only the leading 32 bytes of each 64-byte
slot used (AES-256 key size and SHA256 key size). Hardcode the server key direction with no
configuration knob, because the reference has none for tls-crypt: the server encrypts with
keys[0] (Ke from keys[0].cipher, Ka from keys[0].hmac) and decrypts with keys[1]. Getting
this backwards makes every packet fail HMAC verification from the very first client reset
(RESEARCH Pitfall 2).

The wrap/unwrap file implements the construction from tls_crypt.c, which is MAC-then-encrypt
with a synthetic IV and is not a standard AEAD call — the AEAD helpers in crypto/cipher do
not apply here at all, and neither does any helper that generates its own nonce.
Wire layout: 1 header byte, 8 session ID bytes, an 8-byte tls-crypt packet ID in long form
(4-byte big-endian sequence then 4-byte big-endian unix timestamp), a 32-byte HMAC-SHA256
tag, then AES-256-CTR ciphertext starting at offset 49. The tag is HMAC-SHA256 over the
17 clear-and-authenticated header bytes concatenated with the plaintext; the top 16 bytes of
that tag are the AES-256-CTR IV. On unwrap, verify the tag with hmac.Equal (constant time)
and return an error before decrypting or parsing anything — never a partial-trust path. The
tls-crypt sequence counter is this package's own monotonic counter, guarded so concurrent
Wrap calls cannot emit a duplicate sequence number, and it maintains its own replay window
independent of the reliability layer's.

Build `ovpn.go` with the public surface listed in the plan's `<interfaces>` block. `Serve`
runs a ReadFrom loop over the caller's net.PacketConn. Apply cheap triage before allocating
any per-session state, mirroring tls_pre_decrypt_lite: reject datagrams shorter than the
49-byte tls-crypt prefix, reject datagrams longer than TLS_CHANNEL_BUF_SIZE (2048), reject
header bytes whose opcode falls outside 3..11, and only then unwrap. Dispatch to an existing
session by the pair of remote UDP address and 8-byte session ID; a hard-reset-client-v2 with
key ID 0 from an unknown pair creates a new session. Answer it with a hard-reset-server-v2
carrying a freshly generated 8-byte session ID from the cryptographic RNG (never the
pseudo-random package), this side's reliability packet ID 0 — the reference's reliable
struct is zero-cleared at init, so the first outgoing control packet ID is 0 — and an ACK
array acknowledging the client's packet ID together with the client's session ID. Declare
`OnSession` in Config but do not invoke it in this plan; it fires in plan 01-03 once
`Handshake()` returns nil, and inventing an earlier firing point here would be wrong.
`Close` unblocks the read loop and makes `Serve` return.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet → `Server.Serve` ReadFrom loop | Arbitrary, attacker-controlled UDP datagrams from any source address cross here |
| `internal/tlscrypt.Unwrap` → `internal/wire.ParseControlPacket` | Only authenticated bytes may cross; this is the fail-closed gate |
| Embedder → `ovpn.Config` | Caller-supplied tls-crypt key material and TLS config enter the library |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
