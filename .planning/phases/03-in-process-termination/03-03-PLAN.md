<objective>
Build the deliberately narrow slice of TCP this project needs: server-side accept only,
fixed RTO with doubling backoff, cumulative ACKs, a fixed receive window, a real
bidirectional FIN close, and RST on anything unexpected — enough that stdlib `http.Serve`
can serve a web page to a tunnel client, and nothing more.

**ROADMAP Phase 3 success criterion 3 (first clause, verbatim):** "`ListenTCP(port)`
returns a `net.Listener` that stdlib `http.Serve` accepts on."

This plan delivers the transport. Plan 03-04 closes the remaining `net/http` conformance
gap (deadlines, `CloseWrite`) and runs the actual `http.Serve` round-trip; plan 03-05
builds the site; plan 03-06 proves it against a real client.

Purpose: this is the one piece of the phase with genuine per-connection state and timers,
and the one place where "it works on my happy path" and "it works when a browser does
something ordinary" diverge. The whole plan is structured so that every timer-driven
behavior is assertable in milliseconds against a fake clock, because a TCP bug that only
shows up as a hung `curl` in a Docker run is the most expensive kind of bug this phase can
produce.

## Deliberate deviations from RFC 9293, and why

Each of these is a locked CONTEXT.md decision, not an omission. Every one must carry a
code comment naming the deviation and this rationale, in the citation-header style
`internal/reliable/reliable.go` already uses — so a future reader does not read a
deliberate scope decision as an oversight and "fix" it.

| RFC 9293 mandates | This stack does | Why |
|---|---|---|
| RTO computed per RFC 6298 (SRTT/RTTVAR, Karn's algorithm) | Fixed initial RTO, doubling on each retransmit, capped | D-06. RFC 6298 exists for general-purpose, Internet-facing TCP across unknown paths. Every connection here traverses one already-established VPN tunnel of known, homogeneous quality. |
| Congestion control (slow start, congestion avoidance, fast recovery) | A fixed in-flight byte cap and the peer's advertised window | D-07, "tunnel-quality links only" |
| 2×MSL TIME_WAIT (conventionally ~240s) | A short, named TIME_WAIT duration | D-08's "short-timer TIME_WAIT". Full 2×MSL exists to absorb duplicates from a wide-area path; the tunnel's path is a single point-to-point encrypted link with its own replay window below this layer. |
| Full option set (window scale, timestamps, SACK) | MSS only | D-06 (no SACK), D-07 (fixed window). Window scaling is unnecessary at a 64KB window on a 1500-byte-MTU tunnel. |
| Active open (SYN_SENT, simultaneous open) | Passive open only | D-05, and the project briefing's own "minimal server-side TCP" scope |

**`tcp_segment.go`.** Flag constants (`flagFIN = 0x01`, `flagSYN = 0x02`, `flagRST = 0x04`,
`flagPSH = 0x08`, `flagACK = 0x10`), `tcpHeaderMinLen = 20`, `tcpHeaderMaxLen = 60`,

`parseTCP(payload []byte) (tcpSegment, error)` bounds-checks in `internal/wire`'s order:
`len(payload) >= tcpHeaderMinLen`; `dataOffset := int(payload[12]>>4) * 4` with
`dataOffset >= tcpHeaderMinLen && dataOffset <= len(payload)`; then walks the options
region, honoring end-of-options and NOP and bounds-checking each option's length byte
before advancing — a truncated or zero-length option is a typed error, never an infinite
loop or an out-of-range index. Unknown option kinds are skipped by their length, not
rejected. `buildTCP` emits the header with an optional MSS option (SYN-ACK only), computing
the checksum with `transportChecksum` over the pseudo-header with protocol 6.

Do not verify the inbound TCP checksum — the same reasoning plan 03-01 recorded for the
IPv4 header applies: the packet already passed AEAD authentication below the `Session`
boundary. Compute it correctly on send (a real client's kernel does verify) and say so in a
comment rather than leaving the asymmetry unexplained.

**`tcp_listener.go`.** `func (s *Stack) ListenTCP(port uint16) (net.Listener, error)` (D-01):
registers the TCP 4-tuple demux into plan 03-01's TCP seam field on first use, rejects
port 0 and an already-bound port with typed errors, and returns a listener holding an
accept queue of `defaultBacklog` (16) completed connections. Return the stdlib interface
type, not the concrete type, and add a compile-time `var _ net.Listener` assertion.

The demux type implements plan 03-01's protocol-handler interface. Its handler parses the
segment and looks up a 4-tuple key (client IP, client port, server port — the server IP is
always the stack's own). On a hit, the segment goes to that connection's state machine. On
a miss: a SYN to a listening port creates a new half-open connection (Task 3 bounds this);
anything else gets an RST (Task 3 defines the exact sequencing rules). Both `net.Conn`
returned by `Accept` and every connection object carry `*net.TCPAddr` local/remote
addresses so `http.Server` and any embedder logging sees exactly what a real socket
produces.

`Accept()` blocks on the backlog channel and the listener's `stopCh`; `Close()` is
`sync.Once`-guarded (session.go:463-478's discipline), removes the port from the demux,
unblocks `Accept` with an error wrapping `net.ErrClosed`, and resets every connection still
in the backlog that was never accepted. `Addr()` returns the listening `*net.TCPAddr`.

**`tcp_state.go`.** A `tcpState` type with exactly the states D-05 scopes: LISTEN (held by
the listener, not by a connection), SYN_RCVD, ESTABLISHED, FIN_WAIT_1, FIN_WAIT_2,
CLOSING, TIME_WAIT, CLOSE_WAIT, LAST_ACK, CLOSED. **There is no SYN_SENT and no active
open** — write that as a comment naming D-05, because a reader who knows RFC 9293 will
notice the absence and should find the reason next to it.

One `handleSegment` entry point per connection, called from the demux with the connection's
mutex held, driving: SYN_RCVD → ESTABLISHED on the handshake-completing ACK (validating
that the ACK number equals server ISN+1; anything else gets an RST); in-order data
acceptance and cumulative-ACK emission in ESTABLISHED; and the full bidirectional FIN
sequence of D-08 (local close → FIN_WAIT_1 → FIN_WAIT_2 → TIME_WAIT; peer close →
CLOSE_WAIT → LAST_ACK → CLOSED; simultaneous close → CLOSING → TIME_WAIT). A TIME_WAIT
connection is released after `timeWaitDuration` on a `Clock`-created timer, at which point
its 4-tuple becomes reusable.

For this task, acknowledge every in-order data segment immediately rather than implementing
a delayed-ACK timer. Immediate ACK is correct, costs only bandwidth this project does not
care about, and removes a timer that would otherwise need its own test matrix. Note that as
a deliberate simplification.

**`tcp_conn.go`.** The `net.Conn` implementation, with a compile-time `var _ net.Conn`
assertion. Per-connection state under one mutex: `sndUna`, `sndNxt`, `sndWnd` (the peer's
advertised window), `rcvNxt`, the send buffer of unacknowledged bytes, the in-order receive
buffer, the reorder buffer (Task 2), the send MSS after clamping, the state, and the
timers. `Read` delivers from the in-order receive buffer with ordinary `io.Reader`
streaming semantics — as many bytes as fit in `p`, remainder retained for the next call —
and returns `io.EOF` once the peer's FIN has been consumed and the buffer is drained.
Document the contrast with `Session.Read`'s datagram-shaped retain-and-error contract
(session.go:305-313) so the two are not conflated. `Write` appends to the send buffer and
emits segments up to `min(sendMSS, peer window, in-flight cap)`; it blocks while the window
is closed rather than buffering without bound. `Close` initiates the FIN sequence
(`sync.Once`-guarded), and `LocalAddr`/`RemoteAddr` return the `*net.TCPAddr` pair. The
deadline methods are wired to plan 03-01's `deadlineTimer` in plan 03-04; for this task
they may set the deadline fields without yet unblocking a blocked call, but **must not** be
stubs returning nil — leave a `// plan 03-04` marker and let plan 03-04's own tests be the
gate.

ISN generation: read 4 bytes from `crypto/rand` per connection (RESEARCH.md A2 —
acceptable here because every TCP peer has already passed TLS mutual-cert authentication
and AEAD, so RFC 9293's off-path ISN-prediction threat model does not apply inside the
tunnel). Never derive it from a clock, a counter, or any of this codebase's three existing
packet-ID spaces (Pitfall 4).

**`tcpclient_test.go`.** The test-only minimal TCP client that makes this whole plan

client rejects.

Implement RFC 9293 §3.5.2's RST generation rules exactly, and bound the two pieces of state
an authenticated-but-hostile client can otherwise grow without limit.

**RST generation.** Add one helper that builds and sends an RST for an offending segment,
implementing the RFC's two cases and citing §3.5.2 in its doc comment: if the offending
segment had ACK set, the RST carries `SEG.ACK` as its sequence and does not set ACK; if it
did not, the RST carries sequence 0 and acknowledges `SEG.SEQ + SEG.LEN` with ACK set.
Never send an RST in response to an RST (that is the classic reset loop). Call it from
exactly three places: a SYN to a port with no listener, a segment for a 4-tuple with no
connection, and a handshake-completing ACK whose acknowledgement number is wrong. D-08's
own words are the reason this matters: "browsers must not hang on page loads" — a silently
dropped segment leaves a client retrying until its own timeout, which is exactly the
symptom a hung `curl` in plan 03-06's harness would produce.

Handle an **inbound** RST as the mirror: mark the connection reset, release its 4-tuple,
stop its timers, and make subsequent `Read`/`Write` return a connection-reset error rather
than blocking.

**Backlog bound.** The listener's accept queue holds `defaultBacklog` (16) completed
connections. When a handshake completes and the queue is full, reset the new connection
rather than growing the queue or blocking the demux — the demux runs on the stack's single
read-loop goroutine, so blocking there would stall every session's traffic, not just this
listener's.

**Half-open bound.** Track SYN_RCVD connections per attached session, capped at
`maxHalfOpenPerSession` (8). Beyond the cap, drop the SYN and increment a counter. Make
the cap **per session, not stack-wide** — with several clients attached, a stack-wide cap
would let one authenticated client deny service to every other, which is precisely the
threat RESEARCH.md's Security Domain row names. `TestTCPHalfOpenIsPerSession` is what
proves the isolation. A half-open connection that exhausts its retransmit budget (Task 2)
releases its slot, so an abandoned SYN does not hold a slot forever.

Both constants get doc comments in `internal/reliable/reliable.go`'s style citing
