# Phase 3 — UI Design Contract

> Visual and interaction contract for `examples/tunnelweb` — the tunnel-only example web
> server. This is the ONLY UI surface in this phase (per locked CONTEXT.md/scope note): a
> landing page plus 4 subpages (status, about, echo-test, headers), served as plain embedded
> HTML/CSS with no JS build step, no external assets, no component library, no framework.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — pure Go project, no `package.json`/`components.json`; shadcn init gate is not applicable to this stack |
| Preset | not applicable |
| Component library | none — hand-written semantic HTML, single embedded `<style>` block or `//go:embed`'d `.css` file |
| Icon library | none — text-only labels/status indicators; no icon font, no inline SVG icon set (avoids any external-asset or build-step dependency) |
| Font | system font stack only, no web fonts, no CDN — see Design Tokens below |

**Delivery constraint (locked, not negotiable):** every page must render correctly in any
browser with **zero network access beyond the tunnel itself** — no CDN-hosted fonts, no
external stylesheets/scripts, no analytics beacons, no favicon fetch from an external host. One
embedded stylesheet, inline in each response or served from a single `/style.css` route on the
same netstack listener. Inline `<script>` is acceptable ONLY if the echo-test form cannot be
done as a plain HTML form POST (it can — see Page Structure below — so plan for **zero
JavaScript** unless a later plan discovers a concrete blocker).

## Design Tokens (embedded stylesheet)

Small, self-contained token set — CSS custom properties declared once in `:root`, reused by
every page. This is the entire "design system" for this phase.

```css
:root {
  /* Color — 60/30/10 */
  --color-bg: #ffffff;          /* dominant (60%) */
  --color-surface: #f1f3f5;     /* secondary (30%) */
  --color-border: #d8dde3;
  --color-text: #1a1a1a;
  --color-text-muted: #5f6b7a;
  --color-accent: #2563eb;      /* accent (10%) — see reserved-for list below */

  /* Typography */
  --font-sans: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial, sans-serif;
  --font-mono: ui-monospace, SFMono-Regular, "SF Mono", Menlo, Consolas, monospace;
  --text-sm: 14px;
  --text-base: 16px;
  --text-lg: 24px;
  --text-xl: 32px;

  /* Spacing (8-point scale) */
  --space-xs: 4px;
  --space-sm: 8px;
  --space-md: 16px;
  --space-lg: 24px;
  --space-xl: 32px;
  --space-2xl: 48px;
  --space-3xl: 64px;

  --radius: 4px;
}
```

No dark-mode toggle, no media-query theme switch — one theme only, kept proportionate to the
phase's actual audience (a developer glancing at a proof-of-life page, not a product surface).

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline gaps (e.g. between a status label and its value) |
| sm | 8px | Compact spacing (table cell padding, form field gaps) |
| md | 16px | Default element spacing (paragraph gaps, nav item gaps) |
| lg | 24px | Section padding (card/table container padding) |
| xl | 32px | Layout gaps (between major page sections) |
| 2xl | 48px | Page header to content gap |
| 3xl | 64px | Not used on these small single-column pages — reserved token, no current usage |

Exceptions: none. No touch-target minimum override needed — no icon-only controls exist
anywhere in this phase (nav links and the one form button are all text-labeled).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label / meta | 14px | 400 | 1.5 |
| Heading (page/section title, `h2`) | 24px | 600 | 1.2 |
| Display (site title, `h1`, landing page only) | 32px | 600 | 1.2 |

Exactly 2 weights (400 regular, 600 semibold), exactly 4 sizes. Monospace (`--font-mono`) is
used for *values*, not as a fifth text role — it inherits whichever role's size it appears
inside (e.g. a session ID inside a body-sized table cell stays 16px, just in `--font-mono`
instead of `--font-sans`).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` (`--color-bg`) | Page background |
| Secondary (30%) | `#f1f3f5` (`--color-surface`) | Nav bar background, table/card surfaces, code-style value chips |
| Accent (10%) | `#2563eb` (`--color-accent`) | See reserved-for list — nothing else |
| Destructive | not applicable | No destructive actions exist in this phase (see Copywriting Contract) |

Accent reserved for: nav links (default + hover/focus-visible state), the echo-test form's
submit button ("Send echo"), the `:focus-visible` outline on every interactive element, and the
status page's "tunnel: active" indicator text. Nothing else uses `--color-accent` — body text,
headings, and table borders all use `--color-text`/`--color-border`.

Contrast check (WCAG AA, 4.5:1 body text): `#1a1a1a` on `#ffffff` = ~16.1:1; `#5f6b7a` (muted
text) on `#ffffff` = ~5.1:1; `#2563eb` on `#ffffff` = ~5.2:1 — all pass AA for normal-size text.

## Page Structure & Copy (5 pages)

Internal file/route layout is `examples/tunnelweb`'s own discretion (per RESEARCH.md's
recommended structure); this section is the content/interaction contract each route must
satisfy, not a file layout mandate.

### 1. Landing (`/`)
**Purpose:** first thing a developer sees after the tunnel comes up and they load this address in
a browser inside the client container — immediate, obvious proof the netstack TCP/HTTP path
works.
**Elements:** `<h1>` display-sized title (e.g. "govpn tunnelweb"), one sentence of body copy
explaining what this is ("This page is served entirely inside the OpenVPN tunnel — no TUN
device, no CAP_NET_ADMIN, no process outside this Go binary."), and a `<nav>` with 4 links to
the subpages below, each with a one-line description.
**Interaction:** navigation only, no form.
**Copy for nav links (fixed, exact labels):**
| Link label | Destination | One-line description |
|---|---|---|
| Status | `/status` | Live facts about your tunnel session |
| About | `/about` | What this demo proves and how |
| Echo test | `/echo` | Send a message through the tunnel and get it back |
| Headers | `/headers` | See the raw HTTP headers this server received from you |

### 2. Status (`/status`)
**Purpose:** proves the server can see live, per-session facts about the connected client — the
single most convincing "yes, this is really your session" page.
**Elements:** a definition-list or two-column table of session/tunnel facts, computed
synchronously at request time (no async loading state — see UI Considerations).
**Locked minimum fields** (must appear; render `—` if genuinely unavailable from the public
`Session`/`netstack` API surface at implementation time — do not omit the row):
- Assigned tunnel IP (`Session.AssignedIP()`)
- Server tunnel IP (the address this response was served from)
- Cipher (`AES-256-GCM`, fixed per project scope)
- Session status indicator — text "tunnel: active" in `--color-accent`
**Discretionary additional fields** (include if trivially available, e.g. session ID, connected
duration): planner/executor discretion, subject to the same `—` fallback rule for any field not
cheaply available.
**Values requiring monospace:** any hex/IP/identifier value uses `--font-mono` with
`word-break: break-all` (see UI Considerations, overflow row).

### 3. About (`/about`)
**Purpose:** short static explanation for a developer who wants the "why" behind the demo —
no TUN device, no `CAP_NET_ADMIN`, traffic terminates entirely in the Go process via the
userspace netstack.
**Elements:** 2-4 short paragraphs, fixed authored copy (content discretion per CONTEXT.md).
Must explicitly state the "no TUN device, no CAP_NET_ADMIN" fact in plain language — this is the
project's core value proposition and the one thing this page must not omit.
**Interaction:** none — pure static content.

### 4. Echo-test (`/echo`)
**Purpose:** the one interactive proof: text you submit travels through the tunnel to the
server and back, demonstrating the minimal server-side TCP path end to end (not just a static
GET).
**Elements:** a `<form method="post" action="/echo">` with a single labeled `<textarea
name="msg">` (`<label for="msg">Message to echo</label>`), a submit `<button>Send echo</button>`
styled with `--color-accent`, and — after a successful POST — the page re-renders showing the
echoed value.
**Interaction:** plain HTML form POST, full page reload on submit. No JavaScript required or
expected. Server must HTML-escape the echoed value before rendering it back (XSS hygiene — the
echoed value is untrusted user input even though the "user" is a trusted tunnel peer).
**States:** empty (initial GET, no prior submission), populated (after successful POST, shows
"You sent: {escaped value}"), error (empty/oversized POST body — see Copywriting Contract error
row). See UI Considerations for the full state table.

### 5. Headers (`/headers`)
**Purpose:** echoes the raw HTTP request headers the server actually received — proof the
request genuinely transited the tunnel end to end (not served from a cache or a proxy that
rewrites headers).
**Elements:** a heading reading "{N} headers received" (N = actual count), followed by a
two-column `<table>` (`<th scope="col">Header</th><th scope="col">Value</th>`) listing every
header `net/http` parsed off the request, **sorted alphabetically by header name** for
deterministic, screenshot-stable output. Method + path + Host are called out above the table as
the primary "proof" line (e.g. "GET /headers via Host: 10.8.0.1:8080").
**Interaction:** none — pure GET, no form.
**States:** populated (expected/default — a real browser sends 10-25 headers), empty (zero
headers — see UI Considerations, backstop row).

## Accessibility Basics

- Semantic landmarks on every page: `<header>` (site title/nav), `<main>` (page content),
  `<footer>` (optional, small "served via govpn" note) — no `<div>` soup.
- All interactive elements (nav links, the echo-test button, the textarea) have a visible
  `:focus-visible` outline in `--color-accent`, 2px solid, `outline-offset: 2px` — required
  since this page has no JS and must be fully keyboard-navigable by default browser behavior.
  alone.
- The echo-test `<textarea>` has an explicit `<label for="msg">` — not a placeholder-only label.
- Table headers on the headers/status pages use `<th scope="col">` (or `scope="row"` for a
  definition-list-style status table) so screen readers announce column/row context.
  headers page).
- Color contrast verified above (Color section) — no color-only signaling (the "tunnel: active"
  indicator is text, not a colored dot alone).
- No `autofocus`, no motion/animation of any kind (nothing to prefer-reduced-motion around).

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5). Shape-rooted UI *state*
> coverage across the phase's elements: landing nav (nav), landing/about copy
> (static-content), status page facts (list-collection, fixed cardinality), echo-test form
> (form), headers page (list-collection, variable cardinality).

Applicable state considerations resolved: 12 covered, 1 backstop, 1 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | echo-test form | ✅ covered | Initial GET renders an unfilled `<textarea>` with placeholder "Type something to echo through the tunnel…" and no prior echoed value shown. |
| loading | echo-test form | ✅ covered | Plain HTML POST triggers the browser's native full-page-reload loading indicator; no client-side spinner or JS is used. |
| error | echo-test form | ✅ covered | Empty or oversized (>4KB) POST body re-renders the page with the Copywriting Contract's error copy instead of a blank/broken response. |
| loading | status page (list-collection) | ✅ covered | Status facts are computed synchronously server-side before the HTTP response is written; no async/client-side loading state exists on this stack. |
| partial | status page (list-collection) | ✅ covered | Any locked field not cheaply available from the public Session/netstack API at implementation time renders `—` rather than omitting the row or panicking the handler. |
| overflow | status page (list-collection) | ✅ covered | Session ID / IP / identifier values render in `--font-mono` with `word-break: break-all` inside a bounded-width cell — never forces horizontal scroll. |
| zero-one-many | status page (list-collection) | ⚠ unresolved | Status page is a fixed-cardinality fact list, not a variable collection — planner must confirm the exact field set against the Session/netstack public API surface available at implementation time (locked minimum + discretionary fields listed in Page Structure above; exact final set not lockable before that API exists). |
| empty | headers page (list-collection) | 🧪 backstop | If zero headers are somehow present, render "No headers received" instead of an empty table. Expected to never trigger against a real HTTP client — held out as a backstop check, not a manually-demoed path. |
| populated | headers page (list-collection) | ✅ covered | Default/expected state: a two-column name/value table of every header `net/http` parsed off the request, sorted alphabetically by header name. |
| zero-one-many | headers page (list-collection) | ✅ covered | Heading reads "{N} headers received" (numeral only — "headers" doesn't need singular/plural copy branching). |
| overflow | headers page (list-collection) | ✅ covered | Header values (long `User-Agent`/`Cookie` strings) wrap via `overflow-wrap: anywhere` inside the value column — no horizontal scroll. |
| long-text | headers page (list-collection) | ✅ covered | Same wrap treatment as the overflow row above (de-duplicated resolution — one CSS rule covers both). |
| overflow | landing/about copy (static-content) | ✅ covered | All landing/about copy is short, fixed, author-controlled prose with no dynamic or user-supplied content — no overflow risk. |
| long-text | landing nav (nav) | ✅ covered | Nav labels are 4 fixed short words ("Status", "About", "Echo test", "Headers") — no truncation risk, no dynamic label source. |
