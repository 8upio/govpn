<objective>
Make `ListenUDP` real: unmodified socket-based Go code — anything written against
`net.PacketConn` — round-trips a datagram with a tunnel client through the userspace
netstack, with listeners opened on arbitrary ports at runtime and correct IP→session
routing across several attached clients.

**ROADMAP Phase 3 success criterion 2 (verbatim):** "`ListenUDP(port)` returns a
`net.PacketConn` that unmodified socket-based code uses to round-trip a datagram with a
tunnel client; listeners open on arbitrary ports at runtime and sessions attach/detach with
correct IP→session routing (RTP-style workloads)."

Purpose: UDP is the smaller of the two transports and the one whose contract is a pure
stdlib interface — getting `net.PacketConn` genuinely right here (including the deadline
semantics most hand-rolled implementations skip) is what makes the claim "usable by
unmodified socket-based code" true rather than aspirational.

Output: `netstack/udp.go` — the port demux, the RFC 768 header parse/build with the
pseudo-header checksum, and a `net.PacketConn` implementation with real deadlines.

## Decisions implemented here

| ID | Decision | Where it lands |
|----|----------|----------------|
| D-01 | `Stack.ListenUDP(port) (net.PacketConn, error)` is part of the locked public surface | `ListenUDP` signature returns the stdlib interface type, never a concrete `*udpConn` |
| D-03 | UDP demux by (server tunnel IP, port); listeners open on arbitrary ports at runtime; catch-all port-range API deferred | the port table and its `ErrPortInUse`; no range API |
| D-04 | Outbound fail-closed on source IP | every `WriteTo` goes through `Stack.writePacket` |
| D-12 | Fake-`Session` fast tier, no Docker | `udp_test.go` drives everything through hand-built packets |
| D-14 | Buffer/queue sizes are Claude's discretion, matched to existing precedent | resolved below |
| D-17 | IPv4 only | non-IPv4 addresses rejected with a typed error at `WriteTo` |

## D-14 resolved (this plan's share)

`udpQueueDepth = 64` — the per-listener bounded inbound queue. Overflow drops the newest
datagram with a non-blocking `select`/`default`, exactly as a congested link would and
exactly as `Session.ipInbound` already does at depth 32 (session.go:365-384, D-06 of
Phase 2). 64 rather than 32 because a UDP listener is a fan-in point for every attached
session, not a per-session queue. `maxUDPPayload = 65507` is asserted as the write-side
upper bound (the RFC 768 length field is 16 bits and the 8-byte UDP header plus the 20-byte
IPv4 header come out of it); a larger `WriteTo` returns a typed error rather than
truncating — in practice the pushed `tun-mtu 1500` caps a datagram far below this, and
this stack does not fragment.
</objective>

**Header codec.** `parseUDP(payload []byte) (srcPort, dstPort uint16, data []byte, err
error)` bounds-checks in order: `len(payload) >= udpHeaderLen`; the 16-bit length field at
offset 4 is `>= udpHeaderLen` and `<= len(payload)`; then slices. `buildUDP` appends the

the UDP header (checksum field zeroed) plus the payload. Apply RFC 768's two special rules
explicitly and comment each with the RFC's own reasoning: on send, a computed `0x0000` is
transmitted as `0xFFFF` because an on-wire `0x0000` means "sender computed no checksum"; on
receive, an on-wire `0x0000` skips verification rather than being treated as corrupt.

Harden `udpConn`'s deadline and close semantics until they are indistinguishable from a
real socket's, because that is precisely the claim NET-01 makes.

`ReadFrom` selects over exactly four cases: a queued datagram, the closed channel, the read
deadline's wait channel, and (if the deadline is already expired when entering) an
immediate timeout return. Re-read the deadline's wait channel on each call rather than
caching it — `SetReadDeadline` replaces it, and a cached channel would leave a blocked
reader waiting on a stale timer. `WriteTo` checks the write deadline before building
anything.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Authenticated tunnel peer → UDP port demux | A client chooses the destination port, and therefore which embedder-opened listener its bytes reach |
| UDP listener queue → embedder's `ReadFrom` | The first point at which client-supplied payload bytes cross into caller code the library does not control |
| One session's datagrams → another session's listener view | Several clients share one listener; the `*net.UDPAddr` a listener sees is what an embedder will use for authorization decisions |
| `WriteTo` → `Stack.writePacket` → `Session.Write` | Bytes the embedder constructs cross back into the encrypted tunnel toward a specific client |

## STRIDE Threat Register (ASVS L1 — block on high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-08 | Spoofing | `*net.UDPAddr` reported by `ReadFrom` | high | mitigate | The source address a listener sees comes from the IPv4 header of a packet that already passed the stack's `Attach`-registered source-IP equality check (plan 03-01, T-03-01) — so a client cannot make its datagrams appear to come from another client's tunnel IP, which an embedder might treat as identity. Asserted at this layer by `TestUDPSpoofedSourceNotDelivered`, not only at the IP layer. |
| T-03-09 | Denial of Service | per-listener inbound queue | medium | mitigate | Bounded at `udpQueueDepth = 64` with a non-blocking `select`/`default` drop of the newest datagram, mirroring `session.go:365-384`. | T-03-10 | Tampering | `parseUDP` length handling | high | mitigate | The 16-bit length field is validated as `>= udpHeaderLen` and `<= len(payload)` before any slicing; a datagram whose length field lies is dropped with a typed error. `TestUDPParseNeverPanics` drives every truncation and inconsistent length under `-race`. Same discipline as `internal/wire`'s bounds-checked parse. |
| T-03-11 | Information Disclosure | port scanning from inside the tunnel | low | accept | A tunnel peer can determine whether a given UDP port responds, which is true of any network service. | T-03-12 | Spoofing | outbound datagram source address | high | mitigate | `WriteTo` always builds the IPv4 header with the stack's server tunnel IP as source and sends via `Stack.writePacket`, whose D-04 fail-closed check re-parses and drops anything else.
